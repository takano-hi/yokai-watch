# character 生成の見本画像

- medal と同じ `loadReferenceImage` と２枚の `input_image` の送信処理を使う。
- character の候補はプロンプト関数と参照画像キーのペアにする。１回の乱数選択で両方を決定し、プロンプトと見本の取り違えを防ぐ。選択確率は各50%。
- プロンプト１は既存の `character.png`、プロンプト２は別ファイルの `character-2.png` を使う。画像は `api/src/lib/reference-images/` に配置し、環境変数や追加パッケージは導入しない。
- `character-2.png` は既存画像のコピーを初期値として配置する。２つのファイルは個別に差し替え可能で、異なる見本を使う場合はプロンプト２用の画像を差し替える。
- character には１枚目に人物写真、２枚目に選択した見本を送る。人物の特徴は１枚目から、フォルム・絵柄は２枚目から参照するよう共通の指示を追加する。
- 選択した見本の読み込み・PNG検証が失敗した場合は生成を中止し、OpenAI・R2を呼ばない。別の見本へのフォールバックはしない。既存の生成失敗と同じ扱いでDB登録しない。
- character → medal の生成順を維持する。medal は生成済みcharacterと `medal.png` を参照し、メダルだけの失敗は引き続き任意扱いとする。
- 外部API契約・DB・Web・モックは変更しない。OpenAI・R2をモックし、両方の選択境界・画像の順番・参照画像の読み込み失敗を確認する。
